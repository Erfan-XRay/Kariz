# بازبینی امنیتی پنل (برای ۱٫۰)

[English](../security-review.md) · **فارسی**

این صفحه می‌گوید پیش از ۱٫۰ چه چیزی بررسی شد، چه پیدا شد، چه عوض شد و چه چیزی به‌عنوان محدودیتِ شناخته‌شده ماند. پنل، agentها و مسیر به‌روزرسانی‌شان را پوشش می‌دهد؛ هستهٔ تانل یادداشت‌های خودش را در [امنیت](security.md) دارد.

## چه کسی مهاجم فرض شده

| مهاجم | می‌تواند | نمی‌تواند (طبق طراحی) |
|---|---|---|
| کسی در اینترنت که پورت پنل را پیدا کند | هر درخواستی بفرستد، اتصال‌های زیاد باز کند، رمز و لینک امتحان کند | بفهمد پنل است (هر آدرسی جز مسیر مخفی، ۴۰۴ ساده‌ٔ nginx است)، یا در هر ۱۵ دقیقه از هر آدرس بیش از ۵ راز غلط امتحان کند |
| صفحه‌ای که ادمین وارد‌شده باز می‌کند | مرورگر را وادار به فرستادن درخواست کند | کاری بکند: کوکی `SameSite=Strict` است، هر تغییر headerی می‌خواهد که فقط اپ می‌شناسد، و صفحه نمی‌تواند بدون پرسیدن مرورگر `application/json` بفرستد |
| سروری که تصاحب شده (یک agent) | هر چیزی به پنل جواب بدهد، لینک را رها کند | پنل را وادار به اجرای چیزی کند یا به سرورهای دیگر برسد: پنل جواب‌هایش را فقط به‌عنوان داده می‌خواند |
| شبکهٔ بین پنل و یک سرور | بایت‌ها را بخواند و عوض کند | چیز به‌دردبخوری بخواند یا عوض کند: لینک از خودِ کاریز است (رمزشده، و هر دو سمت کلیدها را ثابت می‌کنند) |
| دانلود آلوده | برنامه‌ای عرضه کند | اجرایش کند: ریلیزها امضا شده‌اند و فایلی که امضایش نخواند پاک می‌شود |
| کسی با یک نسخه از پایگاه‌داده | بخواندش | بدون چیز بیشتر وارد شود یا جای یک سرور را بگیرد: رازها به‌صورت hash ذخیره می‌شوند (Argon2id، BLAKE3)؛ کلیدهای agentها در آن است، پس با حالت `0600` در پوشه‌ای `0700` نگه داشته می‌شود |

**تصاحب پنل چقدر می‌ارزد.** هر که پنل را در دست بگیرد تانل‌های هر سرورِ زیر مدیریتش را در دست دارد (ساختن، توقف، حذف، خواندن لاگ) و می‌تواند سرورها را در یک شبکهٔ خصوصی بگذارد. نمی‌تواند آنجا فرمان اجرا کند و نمی‌تواند برنامه‌ای نصب کند که کلید ریلیز امضایش نکرده باشد. این بهای یک پنل مدیریتی است؛ برای همین آدرس مخفی است، پورت تصادفی است و ورود سخت‌گیر است.

## چه چیزی بررسی شد

| حوزه | نتیجه |
|---|---|
| ورود: hash کردن رمز، رسیدگی به لینک، قفل، sessionها | Argon2id (‏19 MiB، ۲ دور)، لینک‌ها و sessionها فقط به‌صورت hash، لینک یک‌بار کار می‌کند، sessionها فهرست و قابل لغو، کوکی `__Host-`، ‏`Secure`، ‏`HttpOnly`، ‏`SameSite=Strict`. **درست.** |
| CSRF | header ‏`X-Kariz-CSRF` روی هر تغییر، به‌علاوهٔ بدنهٔ JSON، به‌علاوهٔ `SameSite=Strict`. **درست.** |
| تزریق به فایل‌های تانل | هر فیلد تانل مقداری تایپ‌شده است؛ متنی با نویسهٔ کنترلی رد می‌شود؛ فایل را agent می‌سازد، هرگز از پنل گرفته نمی‌شود. یک تست پیدا کرد که پیش از پایان فاز ۱۲ یک خط جدید در آدرس پذیرفته می‌شد؛ رفع و تست شد. **درست.** |
| نام‌ها به‌عنوان مسیر | نام تانل و اینترفیس `[a-z0-9-]` با سقف طول است؛ نسخه‌ها پیش از تبدیل شدن به پوشه بررسی می‌شوند. تست برای `../` و مشابهش. **درست.** |
| فرمان‌هایی که agent اجرا می‌کند | فهرست ثابت: `systemctl`، `journalctl`، `ip`، `ping`، `kariz speedtest`، با آرگومان‌های ثابت و مقدارهای بررسی‌شده، و فقط unitهای `kariz@NAME` و اینترفیس‌های `kz-`. بدون shell. **درست.** |
| هویت agent | یک token لینک به‌علاوهٔ کلیدِ هر agent، که روی یک challenge تصادفی با hash کلیددار و مقایسهٔ زمان‌ثابت ثابت می‌شود؛ کد پیوستن یک‌بار کار می‌کند. **درست.** |
| به‌روزرسانی‌ها | امضای Ed25519 روی فایل چک‌سامی که نام آرشیو را دارد؛ پنل می‌سنجد، هر agent دوباره می‌سنجد و `kariz-manager` هم؛ اگر برنامهٔ تازه بالا نیاید برگشت. **درست**؛ برای خودِ دانلود تغییرهای زیر را ببینید. |
| رازها در جواب‌ها | tokenهای تانل هرگز به مرورگر پنل فرستاده یا در پنل نگه داشته نمی‌شوند؛ پشتیبان رمزشده است. **درست.** |
| اپ وب | بدون `innerHTML` یا `dangerouslySetInnerHTML`؛ متنی که از سرورها می‌آید (لاگ، یادداشت‌های ریلیز، نام‌ها) همیشه به‌عنوان متن نمایش داده می‌شود. **درست.** |
| وابستگی‌ها | `cargo audit` در CI با هر تغییر اجرا می‌شود. |

## چه چیزی پیدا و عوض شد

۱. **سقفی برای اتصال‌های بی‌کار نبود.** یک client می‌توانست اتصال باز کند و چیزی نگوید تا سوکت‌های پنل تمام شود. حالا handshake ‏TLS باید در ۱۰ ثانیه تمام شود، headerهای یک درخواست در ۱۵، و حداکثر ۵۱۲ اتصال هست (اتصال بعدی فوراً بسته می‌شود). با TLS واقعی تست شده.
۲. **جواب‌های API هیچ‌کدام از headerهای سخت‌سازی مرورگر را نداشتند** (فقط فایل‌های اپ وب داشتند). حالا هر جواب زیر مسیر مخفی `Cache-Control: no-store`، `X-Content-Type-Options`، `X-Frame-Options: DENY`، `Referrer-Policy: no-referrer`، یک Content-Security-Policy (برای API ‏`default-src 'none'`؛ برای اپ، اسکریپت، اتصال، فونت و استایل فقط از خودش، بدون object، بدون frame)، HSTS و سیاست‌های cross-origin و permissions دارد. ۴۰۴ برای هر آدرس دیگر دقیقاً همان nginx می‌ماند.
۳. **مجوزهای پایگاه‌داده به هر که پنل را راه انداخته بود بستگی داشت.** کلیدهای agentها در آن است. حالا با هر umask حالت `0600` در پوشه‌ای `0700` است.
۴. **فهرست ریلیز می‌توانست دانلود را به سرویسی روی همان سرور بفرستد** (`http://127.0.0.1:...`؛ فقط تست‌ها به آن نیاز دارند). دانلود فقط آدرس‌های `https` را دنبال می‌کند، مگر اینکه خودِ مخزن به‌عنوان یک مخزن محلی تنظیم شده باشد.
۵. **یک آرشیو می‌توانست هزاران فایل داشته باشد یا به حجم عظیم باز شود.** حالا حداکثر ۵۰۰ ورودی و ۴۰۰ MB، و فقط آن دو برنامه از آن خوانده می‌شوند.
۶. **لاگ audit تا ابد بزرگ می‌شد.** حالا یک سال نگه داشته می‌شود.
۷. **تعداد بررسی‌های هم‌زمان رمز نامحدود بود.** هرکدام حافظه و CPU واقعی می‌خواهد، پس سیلی از آدرس‌های زیاد می‌توانست پنل را ناکارا کند. حداکثر چهار تا هم‌زمان اجرا می‌شود؛ بقیه `429` می‌گیرند.
۸. **تانلی با پورت‌های IPv6 زیاد بی‌صدا رد می‌شد** (یک درخواست به ۱۶ KB محدود بود و ۲۰۰ forward می‌تواند بیش از ۲۰ KB شود). سقف ۶۰ KB است (بایت‌های باز شدن یک stream جای ۶۴ KB دارند)، API برای فراخوانی‌هایی که تانل می‌سازند ۱۲۸ KB می‌پذیرد، و درخواستِ خیلی بزرگ این را می‌گوید.

## محدودیت‌های شناخته‌شده (پذیرفته‌شده، و گفته شده)

- **قفل برای هر آدرس است.** کسی با آدرس‌های زیاد (یک /64 از IPv6) می‌تواند بیشتر امتحان کند؛ هزینهٔ Argon2، دروازهٔ چهار بررسی هم‌زمان و رمزی دست‌کم ۱۰ نویسه‌ای در برابر آن ایستاده‌اند. رمز بلند بگذارید، یا فقط با لینک وارد شوید.
- **گواهی به‌طور پیش‌فرض خودامضاست،** پس اولین بازدید به آنچه نصب‌کننده چاپ کرد اعتماد می‌کند (اثرانگشت را مقایسه کنید). برای برداشتن این گام گواهی خودتان را به کار ببرید (`cert_file`).
- **پنل پیش از ورود می‌گوید رمز گذاشته شده یا نه** (صفحهٔ ورود باید بداند).
- **agent با root اجرا می‌شود** چون سرویس‌ها و اینترفیس‌ها را مدیریت می‌کند. درخواست‌هایش همان فهرست ثابت بالاست، ولی باگ در یکی از آن‌ها باگِ root است؛ کوچک‌اند، اعتبارسنجی و تست شده‌اند.
- **خودِ GRE رمز نیست؛** کاریز آنچه را داخلش می‌رود رمز می‌کند. [شبکه‌های خصوصی](networks.md) را ببینید.
- **پشتیبان‌ها کلیدهای agentها را دارند** (همین باعث می‌شود پنلِ بازگردانده‌شده با آن‌ها حرف بزند)؛ با عبارتی که خودتان انتخاب می‌کنید رمز شده‌اند. هر دو را امن نگه دارید.
- **کلید ریلیز یک کلید است.** اگر لو برود یا گم شود، ریلیزها را دیگر نمی‌شود اعتماد کرد یا ساخت: کلید تازه یعنی برنامهٔ تازه با کلید داخلی تازه، که یک‌بار دستی نصب می‌شود.

## چطور مشکلی را گزارش کنید

یک issue روی مخزن باز کنید، یا اگر هنوز نباید عمومی باشد به‌صورت خصوصی به نگهدارنده بنویسید. لطفاً نسخه را بنویسید (`kariz-panel --version`).
