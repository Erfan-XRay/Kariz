# ترنسپورت Paqet روی TCP خام

Paqet یک ترنسپورت تونل کاریز برای لینوکس و IPv4 است. همان بسته‌های رمزشدهٔ KCP را
جابه‌جا می‌کند که [`kcp`](transports.md) جابه‌جا می‌کند، ولی به‌جای UDP داخل بسته‌های خام
TCP. هر بسته شبیه دادهٔ یک اتصال TCP برقرار است و هیچ دست‌دهی‌ای در کار نیست. برای
مسیرهایی است که UDP را می‌بندند یا کند می‌کنند ولی TCP را رد می‌کنند.

کاریز سربرگ TCP هر بسته را خودش می‌سازد و مسیریابی را به لینوکس می‌سپارد. هیچ چیزی
نصب نمی‌شود و هیچ کار دستی‌ای لازم نیست. سرویس تونل با root اجرا می‌شود، سوکت خام را
باز می‌کند و قواعد فایروالی را که Paqet لازم دارد خودش اضافه می‌کند (بخش
[قواعد فایروال](#قواعد-فایروال) را ببینید). هر دو سرور به کاریز 2.8.0-beta.1 یا
جدیدتر نیاز دارند و 2.8.1 یا جدیدتر بهتر است (بخش «نسخه‌ها» در پایین).

## در پنل

در مرحلهٔ ترنسپورتِ ویزارد تونل، یا در صفحهٔ ویرایش تونل، **paqet** را انتخاب کنید.
بقیه مثل ترنسپورت‌های دیگر است:

- **آدرس.** سرور شنونده مثل ترنسپورت‌های دیگر روی همهٔ آدرس‌های IPv4 خودش گوش می‌دهد و
  به هر اتصال از همان آدرسی جواب می‌دهد که اتصال به آن رسیده؛ پس سروری که چند آدرس
  دارد هم درست کار می‌کند. هیچ آدرسی برای پرکردن نیست.
- **پورت.** هر پورت TCP آزاد. ویزارد یکی پیشنهاد می‌دهد.
- **فقط IPv4.** فقط آدرس‌های IPv4 سرور شنونده برای اتصال پیشنهاد می‌شوند و آدرس IPv6
  خطا می‌گیرد.
- **بدون شبکهٔ خصوصی.** گزینهٔ اجرای تونل روی GRE یا VXLAN برای Paqet خاموش است (بخش «کجا کار
  می‌کند» را ببینید).
- **محک.** وقتی هر دو سرور 2.8.0-beta.2 یا جدیدتر دارند، [محک](panel.md) Paqet را روی
  آدرس‌های IPv4 عمومی در هر دو جهت می‌سنجد و انتخاب نتیجه‌اش ویزارد را پر می‌کند.

## کجا کار می‌کند

- **فقط IPv4.** Paqet هنوز روی IPv6 کار نمی‌کند. آدرس گوش‌دادن و آدرس اتصال باید IPv4
  باشند (یا نامی که به IPv4 می‌رسد).
- **نه داخل GRE یا VXLAN.** از نظر فنی کار می‌کند ولی آنجا فایده‌ای ندارد: فیلتر فقط
  بسته‌های بیرونی GRE یا VXLAN را می‌بیند، نه TCP داخلشان را. روی شبکهٔ خصوصی `kcp` یا
  `tcpmux` هزینهٔ کمتری دارند.
- **مسیری که TCP بدون دست‌دهی را رد کند.** بعضی دیتاسنترها و ارائه‌دهنده‌ها جلوی سرورها
  فایروال حالت‌داری دارند که بسته‌های TCP اتصالی را که باز شدنش را ندیده دور می‌ریزد.
  Paqet از آنجا رد نمی‌شود. آن‌وقت تونل با `handshake timed out` شکست می‌خورد، در حالی که
  `kcp` یا `tcpmux` بین همان دو سرور کار می‌کنند. روی چنین مسیری ترنسپورت دیگری بگیرید،
  یا از ارائه‌دهنده بخواهید پورت را باز کند.

## تنظیم‌هایی که اثر دارند

Paqet همان تنظیم‌های `kcp` را دارد:

- **پروفایل** پیش‌فرض‌های KCP را تعیین می‌کند. `gaming` به‌طور پیش‌فرض FEC را روشن
  می‌کند (۱۰ بستهٔ داده و ۳ بستهٔ توازن) و پروفایل اندازهٔ بافر سوکت را هم تعیین می‌کند
  (۱ مگابایت، و با `ultraspeed` ۴ مگابایت).
- **مالتی‌پلکس** به‌طور پیش‌فرض روشن است و لینک را بین اتصال‌های فورواردشدهٔ زیادی
  تقسیم می‌کند. `[tunnel.mux]` تعداد اتصال‌ها، keepalive و پنجره‌ها را تعیین می‌کند و
  می‌شود خاموشش کرد.
- **تنظیمات KCP** (`[tunnel.kcp]`): حالت زمان‌بندی، پنجره‌ها، MTU، ‏FEC و دیتاگرام. در پنل
  زیر **تنظیمات KCP** در مرحلهٔ ترنسپورت است و فقط برای Paqet اعمال می‌شود.
- **`[tuning]`**: بافر سوکت و علامت DSCP، مثل ترنسپورت‌های دیگر.

## نمونهٔ تونل reverse

بدون پنل: با `kariz token` یک توکن بسازید و همان را در هر دو سمت بگذارید. آدرس و مقصد
فوروارد نمونه را با مقادیر خودتان عوض کنید.

```toml
# Entry (listener)
role = "entry"
mode = "reverse"

[tunnel]
transport = "paqet"
listen = "0.0.0.0:31080"
token = "CHANGE-ME-run-kariz-token"

[tunnel.kcp]
mtu = 1200

[[forward]]
listen = "0.0.0.0:18080"
target = "127.0.0.1:18081"
protocol = "tcp+udp"
```

```toml
# Exit (dialer)
role = "exit"
mode = "reverse"

[tunnel]
transport = "paqet"
remote = "192.0.2.21:31080"
token = "CHANGE-ME-run-kariz-token"

[tunnel.kcp]
mtu = 1200
```

`listen` می‌تواند یک آدرس مشخص سرور هم باشد (`192.0.2.21:31080`) تا فقط روی همان آدرس
گوش بدهد.

## قواعد فایروال

بسته‌های Paqet بدون دست‌دهی TCP داده حمل می‌کنند. بدون قاعده، کرنل به هر کدام پاسخ TCP
Reset می‌دهد و connection tracking آن‌ها را نامعتبر علامت می‌زند. فایروالی که فقط پاسخ
اتصال‌های برقرار را می‌پذیرد (مثل ufw یا firewalld) این بسته‌ها را دور می‌ریزد و تونل
هیچ‌وقت وصل نمی‌شود.

برای همین کاریز چهار قاعدهٔ `iptables` را بالای زنجیره‌هایشان اضافه می‌کند. در سمت
شنونده این قواعد به پورت تونل محدودند (و اگر شنونده روی یک آدرس باشد، به همان آدرس). در
سمت وصل‌شونده به آدرس وصل‌شونده و آدرس و پورت شنونده محدودند، تا هر اتصال دوباره از
همان قواعد استفاده کند:

| جدول و زنجیره | چه بسته‌ای | کار |
| --- | --- | --- |
| `raw PREROUTING` | بسته‌های ورودی تونل | `CT --notrack` |
| `raw OUTPUT` | بسته‌های خروجی تونل | `CT --notrack` |
| `filter INPUT` | بسته‌های ورودی تونل | `ACCEPT` |
| `filter OUTPUT` | TCP Resetهای خروجی تونل | `DROP` |

قواعد توضیح `kariz-paqet pid=<pid>` دارند و با توقف تونل حذف می‌شوند. اگر پردازه به‌زور
بسته شده باشد، اولین تونل Paqet که بعداً روشن شود قواعد باقی‌مانده را پاک می‌کند. برای
دیدنشان `sudo iptables -S | grep kariz-paqet` و `sudo iptables -t raw -S | grep kariz-paqet`
را اجرا کنید.

فایروالی که جلوی سرورهاست (مثل فایروال ارائه‌دهندهٔ ابری) روی خود میزبان نیست. پورت TCP
تونل را آنجا خودتان باز کنید، مثل هر تونل دیگری.

### بدون iptables

اگر `iptables` نصب نباشد یا خطا بدهد، تونل باز هم روشن می‌شود و لاگ سرویس هشدار می‌دهد.
در این حالت قواعد معادل را خودتان بگذارید. متغیرهای زیر را روی هر دو میزبان با آدرس‌ها و
پورت خودتان تنظیم کنید. اگر فایروال با سرویس دیگری مدیریت می‌شود، از قواعد معادل و روش
ذخیره‌سازی همان سرویس استفاده کنید.

```bash
listener=192.0.2.21
dialer=192.0.2.22
port=31080
action=-I
```

روی سمت شنونده:

```bash
sudo iptables -w "$action" INPUT -s "$dialer" -d "$listener" -p tcp --dport "$port" -j ACCEPT
sudo iptables -w "$action" OUTPUT -s "$listener" -d "$dialer" -p tcp --sport "$port" --tcp-flags RST RST -j DROP
```

روی سمت وصل‌شونده:

```bash
sudo iptables -w "$action" INPUT -s "$listener" -d "$dialer" -p tcp --sport "$port" -j ACCEPT
sudo iptables -w "$action" OUTPUT -s "$dialer" -d "$listener" -p tcp --dport "$port" --tcp-flags RST RST -j DROP
```

اگر سیاست خروجی محدود است، ترافیک خروجی تونل را بعد از قاعدهٔ حذف RST مجاز کنید. برای
حذف، همان دستورها را با `action=-D` اجرا کنید.

## تنظیم کارایی

کرنل بسته‌های پورت‌های دیگر را پیش از رسیدن به برنامه فیلتر می‌کند و در سمت وصل‌شونده
بسته‌های آدرس‌های مبدأ دیگر را هم. کاریز بافر بسته را دوباره به‌کار می‌گیرد و قبل از
شروع گفت‌وگوی تازهٔ KCP، بسته را احراز هویت می‌کند.

هر جریان مثل یک اتصال واقعی شمارهٔ sequence و acknowledgment خودش را دارد. پس فایروال
حالت‌دارِ بین راه هر اتصال مالتی‌پلکس را داخل پنجرهٔ خودش می‌بیند. بافر سوکت خام حتی
بالاتر از `net.core.rmem_max` و `wmem_max` روی اندازهٔ بافر سوکت `[tuning]` تنظیم می‌شود
تا بسته‌های یک انفجار ترافیک به‌خاطر پیش‌فرض کوچک از دست نروند.

پیش‌فرض MTU برابر ۱۳۵۰ است. اگر MTU مسیر کمتر است، این مقدار را در هر دو سمت کم کنید.
۱۲۰۰ نقطهٔ شروع است. دست‌کم ۷۰ بایت از MTU مسیر IPv4 کم کنید و با FEC دست‌کم ۸۳ بایت.
سقف تنظیم در کاریز ۱۴۳۰ و با FEC برابر ۱۴۱۷ است.

از پیش‌فرض‌ها شروع کنید. حالت `normal` نسبت به `fast2` با فاصلهٔ بیشتری بسته‌ها را
تخلیه می‌کند. پنجره‌های کوچک‌تر صف را کم می‌کنند و ممکن است روی مسیر طولانی یا پراتلاف
سرعت را پایین بیاورند. FEC بستهٔ اضافی و پردازش بیشتری می‌خواهد؛ وقتی روشنش کنید که
اتلاف بسته واقعاً هست.

## عیب‌یابی

| چه می‌بینید | چرا | چه کنید |
| --- | --- | --- |
| `handshake timed out`، در حالی که `kcp` یا `tcpmux` بین همان سرورها کار می‌کنند | چیزی جلوی یکی از سرورها TCP بدون دست‌دهی را دور می‌ریزد | روی آن مسیر ترنسپورت دیگری بگیرید، یا از ارائه‌دهنده بخواهید پورت را باز کند |
| `paqet needs root or CAP_NET_RAW` | تونل با سرویس کاریز اجرا نمی‌شود | با سرویس `kariz@` یا با root اجرایش کنید |
| `paqet could not add a firewall rule` در لاگ | `iptables` نیست یا خطا داد | قواعد را [دستی](#بدون-iptables) بگذارید |
| `paqet supports IPv4 only` | آدرس گوش‌دادن یا اتصال IPv6 است | آدرس IPv4 را بدهید |
| `old_agent_paqet` در پنل | یکی از سرورها کاریزِ قدیمی‌تر از 2.8.0-beta.1 دارد | به‌روزش کنید (تنظیمات، به‌روزرسانی) |

برای دیدن بسته‌ها، وقتی تونل در حال وصل‌شدن است `sudo tcpdump -ni any 'tcp port 31080'`
را (با پورت خودتان) روی هر دو سرور اجرا کنید. بسته‌ای که از یک سرور خارج می‌شود و هیچ‌وقت
به دیگری نمی‌رسد، در مسیر دور ریخته شده است. بررسی معمولی پورت TCP نمی‌تواند Paqet را
بیازماید، چون هیچ چیزی روی این پورت به اتصال معمولی جواب نمی‌دهد.

## نسخه‌ها

- **2.8.0-beta.1:** خود Paqet. شنونده یک آدرس IPv4 مشخص لازم دارد.
- **2.8.0-beta.2:** قواعد فایروال خودکار گذاشته می‌شوند و محک Paqet را هم می‌سنجد.
- **2.8.1:** شنونده می‌تواند روی همهٔ آدرس‌های IPv4 باشد (`0.0.0.0`). برای سرور
  شنوندهٔ قدیمی‌تر، پنل به‌جایش آدرس IPv4 خود آن سرور را می‌گذارد.

قالب بسته‌ها و کلیدهای مشتق‌شده از توکن در Paqet مختص کاریز است و با پروژهٔ Go هم‌نامش
روی سیم سازگار نیست.
