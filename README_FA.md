# کاریز

[English](README.md) | **فارسی**

کاریز یک هسته‌ی تانل برای اتصال سرورها به هم است که با Rust نوشته شده و سه هدف اصلی دارد:

1. **مصرف کم منابع**: بدون Garbage Collector و با مصرف RAM پایین، مناسب VPSهای ارزان.
2. **عبور از DPI**: transportها و لایه‌های استتار قابل تعویض‌اند؛ اگر روشی بسته شد، بدون دست زدن به هسته عوضش می‌کنیم.
3. **بیشترین سرعت**: مسیر داده بدون dispatch پویا، سوکت‌های تنظیم‌شده و پروفایل‌های مخصوص هر کاربرد.

> وضعیت: **نسخه‌ی 0.1.0، مراحل اولیه‌ی توسعه.** فعلاً فقط transport ساده‌ی `tcp` پیاده شده است.
> نقشه‌ی راه در [docs/ROADMAP.md](docs/ROADMAP.md).

## مفاهیم

| اصطلاح | معنی |
|---|---|
| **entry** | سروری که کاربرها به آن وصل می‌شوند (مثلاً سرور ایران). قوانین `[[forward]]` روی این سمت تعریف می‌شوند. |
| **exit** | سروری که به مقصد واقعی وصل می‌شود (مثلاً سرور خارج). |
| حالت **reverse** | سمت exit به entry وصل می‌شود و چند کانکشن آماده نگه می‌دارد. |
| حالت **direct** | سمت entry برای هر اتصال کاربر به exit وصل می‌شود. |

دو طرف با یک توکن مشترک همدیگر را احراز هویت می‌کنند. خود توکن هیچ‌وقت روی شبکه ارسال نمی‌شود.

## شروع سریع

<div dir="ltr">

```bash
cargo build --release
./target/release/kariz token          # ساخت توکن مشترک
kariz run -c configs/entry-reverse.toml   # روی سرور entry
kariz run -c configs/exit-reverse.toml    # روی سرور exit
kariz check -c config.toml                # بررسی درستی کانفیگ
```

</div>

نمونه‌ی کانفیگ‌ها در پوشه‌ی `configs/` و فایل سرویس systemd در `systemd/kariz.service` است.

## پروفایل‌ها

| پروفایل | کاربرد |
|---|---|
| `balanced` | پیش‌فرض |
| `throughput` | بافر بزرگ برای انتقال حجیم |
| `gaming` | بافر کوچک، keepalive کوتاه‌تر، کمترین تأخیر |

هر مقداری را می‌توان در بخش `[tuning]` تغییر داد.
